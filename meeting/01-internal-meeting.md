## 회의 목적

고객사 미팅에서 **정확하고 일관된 정보**를 전달하기 위해, 개발팀 내부에서 다음 사항을 먼저 합의한다:

1. 각 POC 구현 가능성에 대한 팀 공통 입장
2. 기술 스택 및 아키텍처 선택의 근거 정리
3. 고객사에 요청할 사전 준비 사항 우선순위
4. 일정·예산·리스크에 대한 현실적인 입장 통일

## 의제 2: LLM 모델 선정 및 인프라 구성 확정

> 참조: [LLM 개선 상세](../improvements/ai-llm.md) | [H/W 인프라](../infra/hw-infrastructure.md) | [S/W 인프라](../infra/sw-infrastructure.md)

### 2-1. 선정 모델 검토

| 역할 | 모델 | 라이선스 | VRAM | 주요 검토 사항 |
|------|------|:-------:|:----:|-------------|
| **행정 문서 생성** | Gemma 4 31B-it (Q4_K_M) | Apache 2.0 | 19.6 GB | A40 × 1 기준 운영 가능 여부 |
| **멀티모달 Vision** | Gemma 4 E4B (BF16) | Apache 2.0 | 15.1 GB | OCR 보조로 활용 계획 |
| **한국어 RAG 임베딩** | KURE-v1 (560M) | Apache 2.0 | 3 GB | 한국어 규정 검색 정확도 |
| **OCR** | PaddleOCR | Apache 2.0 | CPU | HWP/PDF 문서 처리 |

**A40 × 1장 동시 운영 시 VRAM 계획**:
- 31B Q4_K_M: 19.6 GB + E4B BF16: 15.1 GB = **합계 34.7 GB** (여유 13.3 GB)
- 전체 라이선스: Apache 2.0 → 별도 계약 불필요

**결정 필요 사항**:
- [ ] A40 × 1 vs × 2 최종 선택 (POC 데모 안정성 기준)
- [ ] Gemma 4 성능 부족 시 대안 모델 준비 여부 (Qwen2.5 32B Apache 2.0 — 한국어 성능 양호)
- [ ] 임베딩 모델 KURE-v1 성능 사전 검증 일정

### 2-2. GPU 서버 조달 현황 점검

> 참조: [H/W 인프라 — GPU 조달](../infra/hw-infrastructure.md#1-gpu-서버--최우선-조달-항목)

**고객사 서버 현황 파악 전 내부 입장 정리**:

| 시나리오 | 우리 입장 | 고객사 요청 방향 |
|---------|---------|--------------|
| 고객사 A40 보유 | 즉시 POC 착수 가능 | 활용 요청 |

| 클라우드 GPU 제안 | 내부망 정책 확인 후 결정 | 보안팀 검토 요청 |

## 의제 3: 외부 시스템 연동 전략 합의

> 참조: [외부 시스템 사전 준비](../04-external-prerequisites.md) | [감사 데이터 요건](../05-audit-data-requirements.md)

### 3-1. ERP 연동 방식

| 연동 방식 | 장점 | 단점 | 우리 권장 |
|---------|------|------|---------|
| DB Direct (Read-Only) | 가장 빠름, 실데이터 즉시 | 보안 심의 필요, 스키마 파악 | **1순위** |
| ERP API (공식 연동) | 공식 방식, 안전 | 개발 기간 추가, API 문서 필요 | 2순위 (장기) |
| 파일 기반 (CSV/Excel 내보내기) | 즉시 가능, 리스크 없음 | 실시간 아님, 수동 작업 | POC 초기 임시 |

**결정 필요 사항**:
- [ ] ERP 연동 1순위 방식 내부 합의 후 고객사에 제안
- [ ] Read-Only 계정 발급 요청 시 필요 테이블 목록 준비 (데이터 엔지니어 담당)

### 3-2. 그룹웨어 연동 방식

| 연동 방식 | POC 적합성 | 비고 |
|---------|:--------:|------|
| REST API (공식) | 중 | API 문서·계정 발급에 2~4주 소요 |
| DB Direct | 중 | 그룹웨어 DB 구조 파악 필요 |
| Mock 데이터 (임시) | 높음 | 즉시 개발 착수 가능, 실연동 병행 |

**결정 필요 사항**:
- [ ] POC 1 기간 중 Mock vs 실연동 전략 (추천: Mock으로 착수 + 실연동 병행 협의)
- [ ] 그룹웨어 API 담당자 연결 시점

### 3-3. 감사 DB 접근 전략

> 참조: [감사 데이터 요건 상세](../05-audit-data-requirements.md)

**필요 데이터 및 협의 포인트**:
```
[P0 — 개발 착수 전 필수]
□ 감사 DB 읽기 계정 (법인카드, 출장비, 계약 테이블)
□ 1년치 이상 이력 데이터 (이상탐지 기준값 산출용)
□ 개인정보 마스킹 정책 합의

[P1 — 2주 내]
□ 이상 거래 판단 기준 (업무 규정 기반)
□ 감사 부서 담당자 협의 일정
```
