# 과제 2 ERP-그룹웨어 동기화 — 외부 의존성

## 1. 🔴 P0-1 그룹웨어 Write 권한 (최중요)

| 필요 작업 | Read | Write |
|---------|:---:|:---:|
| 인사 정보 조회 | ✅ | — |
| 조직도 조회 | ✅ | — |
| **직원 정보 업데이트** | — | ✅ |
| **부서 변경 반영** | — | ✅ |
| **조직도 수정** | — | ✅ |

**Write 권한 확보 단계**:
1. 그룹웨어 벤더 정책 확인 (2~4주)
2. 고객사 IT 보안팀 승인 (2~3주)
3. 방화벽·IP 화이트리스트 (1~2주)
**총 소요**: 4~8주

## 2. ERP 측 제공 필요

| 뷰/테이블 | 용도 |
|---------|------|
| `V_ALLI_HCM_EMPLOYEE_FULL` | 인사 마스터 (전체 필드) |
| `V_ALLI_HCM_ORG_CHART` | 조직도 (계층 구조) |
| `V_ALLI_HCM_CHANGE_LOG` | 최근 변경 이력 (증분 동기화용) |

## 3. 사원코드 매핑

ERP와 그룹웨어의 사원코드가 다를 경우:
- `EMP_CD_MAPPING` 테이블 필요 (erp_emp_cd ↔ gw_emp_cd)
- 고객사 IT팀에서 초기 매핑표 제공

## 4. 동기화 정책 결정 (D2-01)

| 방식 | 장단점 |
|------|------|
| **ERP → 그룹웨어 단방향** ⭐ 권장 | 단순·안전, ERP가 원본 |
| 양방향 | 충돌 해결 복잡 |
| 선택 필드 양방향 | 세밀하지만 테스트 부담 |

## 5. 동기화 주기 (D2-02)

- 실시간 (ERP Webhook) — 그룹웨어 부하 고려
- **30분 주기** ⭐ 권장
- 일배치 — 실시간성 부족

## 6. 동기화 대상 필드 (D2-03)

```
기본 (P0): 이름, 사번, 부서, 직급
조직도 (P0): 부서 구조
연락처 (P1): 이메일, 전화번호
휴가 일수 (P2): 과제 3 연계
```

## 7. 리스크

- 그룹웨어 벤더 API 부재 → DB Direct (보안 위험 ↑)
- 대량 변경 (신년 조직개편 500명) → 배치 크기 100건 제한
- 충돌 (양쪽 동시 수정) → ERP 우선 정책
